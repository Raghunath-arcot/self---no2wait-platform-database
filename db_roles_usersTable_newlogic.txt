* Udemy

---

 STEP 1 — Add a Core `users` Table

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    is_email_verified BOOLEAN DEFAULT FALSE,
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

This becomes your **single login identity table**.

---

STEP 2 — Modify Existing Tables (Minimal Change)

### 🔹 Modify `authors`

```sql
ALTER TABLE authors
ADD COLUMN user_id UUID UNIQUE,
ADD CONSTRAINT fk_author_user
FOREIGN KEY (user_id)
REFERENCES users(id)
ON DELETE CASCADE;
```

Now:

* `authors` no longer owns email/password
* It references `users`

---

Modify `exam_users`

```sql
ALTER TABLE exam_users
ADD COLUMN user_id UUID UNIQUE,
ADD CONSTRAINT fk_exam_user_user
FOREIGN KEY (user_id)
REFERENCES users(id)
ON DELETE CASCADE;
```

Same logic.

# 🔥 What This Achieves

Now:

| users             | authors        | exam_users      |
| ----------------- | -------------- | --------------- |
| One row per email | author profile | learner profile |

One email → One users row
Multiple profiles allowed.

# 🚀 Registration Logic (Modified, Not Rewritten)

## Register Author

1. Check `users` by email
2. If not exists → create user
3. Insert into `authors` with user_id

If user exists:

* If already has author row → reject
* Else → create author profile only

---

## Register Exam User

Same logic.

---

# 🔐 Login (Single Endpoint Now)

```java
POST /api/auth/login
```

Flow:

1. Find in `users`
2. Validate password
3. Check if exists in `authors`
4. Check if exists in `exam_users`
5. Return roles array

Example response:

```json
{
  "email": "raghu@n2w.dev",
  "roles": ["AUTHOR", "EXAM_USER"]
}
```
